## 一句话总结 / One-liner

Cosmos 3 提出了一种统一混合 Transformer 架构，首次将语言、图像、视频、音频与动作序列的理解与生成集成于单一模型中，在多项理解和生成任务上达到 SOTA，并作为具身智能通用骨干网络。  
Cosmos 3 introduces a unified mixture-of-transformers architecture that jointly handles understanding and generation of language, image, video, audio, and action sequences, achieving SOTA across diverse tasks and serving as a general-purpose backbone for embodied agents.

## 动机 / Motivation

### 中文概述
- **要解决的问题**：当前的物理 AI 智能体通常需要拼接多个独立模型——视觉语言模型（VLM）用于理解和推理，视频生成模型用于世界模拟，视觉-语言-动作模型（VLA）或世界-动作模型（WAM）用于动作预测。这种碎片化架构计算效率低，且不利于表征共享和联合学习。
- **现有工作的缺口**：理解和生成长期被孤立处理，缺乏一个统一框架来同时支持感知、推理、世界模拟和动作预测。
- **核心出发点与关键观察**：理解需要对世界未来演化和动作后果的推理，而生成依赖于对世界和智能体行为的紧凑结构表征。因此，将两者统一对于物理 AI 至关重要。Cosmos 3 旨在通过一个全模态（omnimodal）模型，统一这些分散的能力，消除任务特定且割裂的流水线。

### English Summary
The paper aims to solve the fragmentation in Physical AI, where separate models handle understanding (VLMs), world simulation (video generators), and action prediction (VLAs/WAMs). This separation is limiting because understanding requires reasoning about future world evolution and action consequences, while generation relies on structured representations of the world and agent behaviors—two inherently coupled capabilities. Cosmos 3 unifies these into a single framework for scalable learning through shared representations and joint multi-task supervision.

## 核心方法 / Core Method

### 中文概述
- **总体框架**：Cosmos 3 是一个全模态世界模型家族，能够联合处理和生成语言、图像、视频、音频和动作序列。它根据输入-输出配置，无需结构修改即可在多种模式下运行：作为 VLM、文本到图像生成器、视频生成器（文本到视频、图像到视频、视频到视频）、同步音视频生成器、以及世界-动作模型。
- **核心机制**：
  - **多模态编码器**：分别采用图像/视频编码器、音频编码器和动作编码器，将各种模态转换为 token 序列。
  - **Token 排列与生成模式**：支持灵活的输入-输出组合，通过特定的 token 排列和生成模式控制推理与生成流程。
  - **混合 Transformer（Mixture-of-Transformers, MoT）架构**：核心创新是 Dual-Tower Layer Structure 和 Dual-Stream Joint Attention。这种设计允许不同模态的特征在各自塔中处理，同时通过联合注意力机制进行跨模态交互，实现高效的多模态融合与生成。
  - **多模态位置嵌入**：提出一种统一的位置索引分配机制和绝对时间调制策略，为不同模态（特别是视频和音频的时间维度）提供一致的时空位置表征。
  - **模型变体**：提供 Cosmos3-Super 和 Cosmos3-Nano 等不同规模版本，以及针对具体下游任务的后训练变体（如 Text2Image, Image2Video, Policy-DROID）。
- **与相关工作的区别**：相比此前的多模态模型（如单纯的语言-视觉模型或视频生成模型），Cosmos 3 首次将动作序列作为一等公民集成到统一的理解-生成框架中，真正实现了全模态处理，而非仅在视觉-语言两个模态上做融合。

### English Summary
The core method is a Mixture-of-Transformers (MoT) architecture with Dual-Tower layers and Dual-Stream Joint Attention, which jointly processes language, image, video, audio, and action tokens. The design includes modality-specific encoders, flexible token arrangement for multiple input-output configurations, and a unified multimodal position embedding that handles temporal dimensions consistently. This allows a single model to act as a VLM, video generator, audio-visual generator, or world-action model without architectural changes, distinguishing it from prior work that treats understanding and generation in isolation.

## 一句话总结 / One-liner

SpecFlow 将多模态空间推理的中间视觉思维压缩为固定大小的离散余弦（DCT）表示，通过 flow matching 逐步更新低频到高频的谱系数，并用无分类器引导使文本思维驱动视觉状态演化，在保持推理性能的同时实现最高 2.1 倍的计算与 KV 缓存降低。  
SpecFlow compresses intermediate visual thoughts into a fixed-size DCT workspace and updates it progressively from low- to high-frequency coefficients via flow matching with classifier-free guidance, reducing computation and KV cache up to 2.1× without sacrificing reasoning performance.

## 动机 / Motivation

### 中文概述
现有的多模态空间推理（例如 MVoT）在推理链中反复生成图像 token 作为中间“思维”，这导致文本和视觉 token 交替堆积，上下文长度与 KV 缓存规模随推理跳数线性增长，迅速耗尽上下文窗口、加剧内存带宽压力、并带来高延迟。  
已有缓解方法分为两类：(1) 显式 token 剪枝，依赖启发式重要性判据，无法适应多跳推理中空间线索的跨步复用，容易过剪或欠剪；(2) 隐式连续潜在推理，虽然将中间状态内化，但缺乏显式监督和可解释性，难以对齐离散的空间状态，在复杂空间推理任务上表现不佳。  
本工作观察到：空间推理的中间视觉思维通常只需要全局布局、物体关系等抽象、稀疏的线索，而非像素级细节。因此，直接生成像素空间的视觉思维引入了不必要的自由度和成本。  
SpecFlow 以此为出发点，将中间视觉思维表示为一个紧凑的、频率受控的演化空间状态，利用 DCT 的能量压缩特性，仅保留低阶频率捕捉全局结构，仅在需要更高空间精度时才引入高频细节，从而从根本上解耦内存消耗与推理深度。

### English Summary
Multimodal spatial reasoning chains that interleave textual and visual thoughts lead to context/KV-cache explosion because each visual thought contributes hundreds of tokens per hop. Prior efforts (token pruning, latent reasoning) fail to handle multi-hop dynamics or lack explicit controllability. The paper observes that intermediate visual thoughts require only sparse, structural cues rather than pixel-level detail. SpecFlow thus proposes a compact, frequency-limited visual workspace in the discrete cosine domain, which naturally preserves global layout while progressively adding detail on demand, breaking the dependency between reasoning depth and memory.

## 核心方法 / Core Method

### 中文概述
SpecFlow 采用 **混合生成流程**：文本思考仍以自回归方式生成，而视觉思考则通过一个基于流的确定性状态迁移实现，条件为当前文本思考与上一时刻的视觉状态，不再将过往视觉 token 留存于上下文中。  
**频谱表示**：将视觉工作区通过块 DCT 投影到固定尺寸的离散余弦空间，利用 DCT 强能量压缩特性，低频系数主要编码全局布局与关系，高频系数捕捉纹理细节。  
**频谱渐进分配**：在 flow 时间步上定义一个非递减的二进制掩码，限定激活的 DCT 系数范围（从低频到高频），从而在早期时间步只更新少量低频系数以建立全局结构，在推理后期逐步解锁高频系数进行细节修正。  
**余弦空间 flow matching**：在 DCT 域学习一个确定性的速度场，仅对当前激活的频谱系数进行更新，条件为当前文本提示和上一视觉状态。这避免了扩散模型的多步随机采样，只需极少的固定求解器步数即可完成一跳视觉状态更新。  
**无分类器引导**：自回归生成的文本轨迹作为控制信号，以无分类器引导的方式驱动 flow 更新，确保视觉状态演化与语言意图对齐，而无需将视觉 token 附加到上下文里。  
最终，SpecFlow 维护一个固定尺寸的视觉工作区，其更新仅依赖当前状态与累积文本轨迹，实现了 **记忆开销与推理跳数无关** 的轻量多跳推理。

### English Summary
SpecFlow’s core is a hybrid autoregressive text chain coupled with a deterministic visual state transition via flow matching in the DCT domain. The visual workspace is projected to fixed-size block DCT coefficients, with a progressive frequency mask that expands from low to high frequencies over flow time. Flow matching updates only the active coefficients conditioned on the current textual thought and previous visual state, using classifier-free guidance to steer the update. This yields a bounded visual workspace with negligible memory growth regardless of reasoning hops.

### 中文概述

## 核心方法 / Core Method

### 中文概述
- **整体框架**：OmniDreams 以 Cosmos 扩散模型为基座，经过中训练（mid‑training）和后训练（post‑training）得到能够自回归生成动作条件视频的世界模型。它与 Alpamayo 1 策略模型和 AlpaSim 仿真运行环境共同构成闭环系统。
- **核心机制**：
  1. **条件生成**：模型接受三个条件输入——由 HD 地图和 3D 框渲染的“世界‑场景”抽象图（编码道路结构、车辆、行人等，同时传递未来 ego 轨迹）、文本提示（描述天气、光照等），以及来自过去帧的 KV 缓存，从而生成下一帧七摄像头视图。
  2. **自回归中训练**：采用 Diffusion Forcing 因果噪声调度和 Self Forcing 策略，在训练时模拟推理时的自回归过程，弥合训练‑测试差距，实现长序列一致生成。
  3. **蒸馏与实时推理**：通过分布匹配蒸馏（DMD）将多步扩散减少为少数几步，结合流式注意力设计（StreamingLLM 风格的 attention‑sink 和 ring attention），在单卡或16卡 GPU 上达到 68–105 FPS 的 720p 实时性能。
  4. **多视图一致性**：对每个相机视图独立渲染抽象图，并联合生成，保证多相机间的几何与语义一致性。
- **与最相近工作的区别**：相较其他生成式驾驶世界模型（如 GAIA‑2、Vista），OmniDreams 强调真正的闭环交互性（而非离线 rollout），内建流式 KV 缓存和少步蒸馏以保证每段推理延迟低于实时，并与已发布的策略栈（Alpamayo 1）和模拟器基础设施（AlpaSim）深度绑定。

### English Summary
OmniDreams is built by mid‑ and post‑training the Cosmos diffusion model. It autoregressively generates multi‑view action‑conditioned videos conditioned on a “world‑scenario” abstract map (HD map + 3D agents), text prompts, and a streaming KV cache. It uses Diffusion Forcing causal noise and Self Forcing during training to close the train‑test gap, then applies distribution matching distillation and streaming attention (attention‑sink, ring attention) to achieve real‑time (68–105 FPS at 720p) inference. The model is deeply integrated with the open AlpaSim orchestrator and Alpamayo 1 policy, making it a truly interactive closed‑loop simulator, unlike prior generative world models.

## 个人思考 / Personal Takeaways

- **系统集成的标杆意义**：该工作不只是提出一个新模型，而是展示了从基座模型到实时推理服务、再到与策略引擎和仿真器对接的完整工程链路，为后续学术研究如何将生成模型落地为可用的开发工具提供了清晰蓝图。
